Docker 实战笔记 ​

面向生产环境的 Docker 知识体系，涵盖日常开发、部署运维和问题排查全流程。

一、核心概念 ​

概念速览 ​

概念说明类比
镜像 (Image)只读模板，包含操作系统、运行环境和应用程序类/模板
容器 (Container)镜像的运行实例，可启动/停止/删除对象/实例
仓库 (Registry)存储和分发镜像的中央仓库GitHub
Dockerfile描述镜像构建步骤的自动化脚本配方
卷 (Volume)容器外持久化存储数据U盘
网络 (Network)容器间通信的隔离虚拟网络虚拟交换机

架构 ​

Docker Client → REST API → Docker Daemon → containerd → runc → 容器
                                     ↓
                                Registry
Docker Client → REST API → Docker Daemon → containerd → runc → 容器
                                     ↓
                                Registry
1
2
3
  • Docker Client: CLI 工具，向 Daemon 发送 REST 请求
  • Docker Daemon (dockerd): 守护进程，管理镜像、容器、网络、卷
  • containerd: 容器运行时管理层，负责容器生命周期
  • runc: 符合 OCI 规范的底层容器运行时
  • Registry: 镜像仓库（Docker Hub、阿里云 ACR、Harbor 等）

指令详解 ​

指令作用注意事项
FROM指定基础镜像尽量用 Alpine / slim / distroless
RUN执行构建命令每一条 RUN 创建一个层，尽量合并
CMD默认启动命令可被 docker run 参数覆盖
ENTRYPOINT容器入口点常与 CMD 配合作为默认参数
COPY复制文件保留权限，推荐替代 ADD
ADD复制文件（自动解压 tar）有安全风险，非解压场景用 COPY
WORKDIR设置工作目录自动创建，用绝对路径
ENV环境变量（构建和运行时）持久化到镜像
ARG构建参数（仅构建时）不留在最终镜像
EXPOSE声明端口文档作用，不实际发布
VOLUME声明匿名挂载点数据库等持久化路径
USER运行用户安全必选项，避免 root
LABEL元数据组织镜像、版本管理
HEALTHCHECK健康检查生产必需
SHELL指定 shell默认 /bin/sh -c
STOPSIGNAL停止信号默认 SIGTERM

缓存规则：

  • 当前层内容未变且父层缓存命中 → 使用缓存

容器退出码 ​

退出码含义常见原因
0正常退出SIGTERM 正常关闭
1一般错误启动失败、配置错误
2误用参数错误、缺少环境变量
126权限不足文件无执行权限
127命令未找到路径错误
128+N信号退出137 (SIGKILL=9), 143 (SIGTERM=15)
137OOM Kill内存超限
139段错误内存访问越界
143SIGTERM 退出docker stop 正常关闭
bash
docker inspect -f '{{.State.ExitCode}}' my-container
docker inspect -f '{{.State.OOMKilled}}' my-container
dmesg | grep -i "out of memory"
