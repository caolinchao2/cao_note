Redis ​

高性能缓存与分布式存储，Java 开发者视角的 Redis 全面指南。

一、Redis 概述 ​

1.1 什么是 Redis ​

Redis（Remote Dictionary Server）是一个开源的、基于内存的数据结构存储系统，通常被称为 内存数据存储 或 缓存中间件。它采用 key-value 的存储模式，支持多种数据结构：

  • 字符串（String）
  • 哈希（Hash）
  • 列表（List）
  • 集合（Set）
  • 有序集合（Sorted Set / ZSet）
  • 流（Stream）
  • 位图（Bitmap）
  • 地理空间（Geo）
  • 超长日志（HyperLogLog）

Redis 所有数据都存储在内存中，因此读写速度极快（通常微秒级），同时支持数据持久化到磁盘，避免数据丢失。

1.2 核心特性 ​

特性说明
纯内存操作读写性能可达 10 万+ QPS
单线程模型6.0 之前单线程处理命令，避免并发竞争（6.0+ 多线程 IO，但命令执行仍单线程）
丰富的数据结构支持 String、Hash、List、Set、ZSet 等
持久化RDB 快照、AOF 日志、混合持久化
高可用主从复制、哨兵模式、Redis Cluster
分布式原生集群、客户端分片、代理方案
Lua 脚本原子性执行脚本，实现复杂操作
事务MULTI/EXEC 批量命令执行
发布/订阅Pub/Sub 消息通信
过期策略支持 key 级别 TTL 过期

1.3 使用场景 ​

场景说明
缓存最常用场景，减轻数据库压力，提升响应速度
分布式锁利用 SETNX + Lua 脚本实现跨进程互斥
计数器INCR/DECR 实现点赞数、访问量、库存扣减
排行榜ZSet 实现实时排行
Session 共享统一存储用户会话，解决集群登录态问题
消息队列List 或 Stream 实现异步消息通信
延迟队列ZSet 按时间分数轮询到期任务
布隆过滤器Bitmap 或 RedisBloom 模块实现海量数据快速判存
限流滑动窗口 + ZSet 或令牌桶实现接口限流
分布式 IDINCR 命令生成全局唯一序列号
UV 统计HyperLogLog 在大数据量下极省内存
秒杀系统缓存预热 + 原子扣减 + 限流

@Autowired
private RedisTemplate<String, Object> redisTemplate;

// 存储用户信息
public void saveUser(User user) {
    String key = "user:" + user.getId();
    Map<String, Object> map = new HashMap<>();
    map.put("name", user.getName());
    map.put("age", user.getAge());
    map.put("email", user.getEmail());
    redisTemplate.opsForHash().putAll(key, map);
    redisTemplate.expire(key, 1, TimeUnit.HOURS);
}

// 获取用户信息
public Map<Object, Object> getUserMap(Long id) {
    return redisTemplate.opsForHash().entries("user:" + id);
}

// 购物车 - 添加商品
public void addToCart(Long userId, Long skuId, Integer count) {
    redisTemplate.opsForHash()
        .increment("cart:" + userId, String.valueOf(skuId), count);
}

// 购物车 - 获取商品数量
public Integer getCartItemCount(Long userId, Long skuId) {

@Autowired
private RedisTemplate<String, Object> redisTemplate;

// 生产者
public void sendMessage(String queueName, Object message) {
    redisTemplate.opsForList().rightPush(queueName, message);
}

// 消费者（阻塞获取）
public Object consumeMessage(String queueName, long timeout) {
    // BLPOP 阻塞获取
    List<Object> result = redisTemplate.opsForList()
        .leftPop(queueName, timeout, TimeUnit.SECONDS);
    // 或者使用 rightPopAndLeftPush 实现可靠队列
    return result;
}

// 最新 N 条评论
public void addComment(Long postId, String comment) {
    String key = "comments:" + postId;
    redisTemplate.opsForList().leftPush(key, comment);
    // 只保留最新 100 条
    redisTemplate.opsForList().trim(key, 0, 99);
}

public void consume(String streamKey, String group, String consumer) {
    List<MapRecord<String, Object, Object>> records = 
        redisTemplate.opsForStream()
            .read(Consumer.from(group, consumer),
                  StreamReadOptions.empty().count(10).block(Duration.ofSeconds(2)),
                  StreamOffset.create(streamKey, ReadOffset.lastConsumed(group)));
    
    for (MapRecord<String, Object, Object> record : records) {
        try {
            // 处理消息
            processMessage(record.getValue());
            // 确认消息
            redisTemplate.opsForStream()
                .acknowledge(streamKey, group, record.getId());
        } catch (Exception e) {
            // 处理失败——消息仍在 PEL 中，可重新消费
            log.error("消息处理失败: {}", record.getId(), e);
        }
    }

六、缓存问题（重点） ​

缓存的引入虽然提升了系统性能，但也带来了一系列经典问题。这里详细分析三种最常见的缓存问题及其解决方案。

6.1 缓存穿透 ​

定义： 请求查询一个不存在的数据。缓存和数据库中都没有，导致每次请求都穿过缓存直达数据库。

危害： 恶意攻击者利用不存在的 key 大量请求，压垮数据库。

解决方案：

方案一：缓存空值 ​

java
public User getUser(Long id) {
    // 1. 查缓存
    User user = (User) redisTemplate.opsForValue().get("user:" + id);
    if (user != null) {
        return user;
    }

    // 2. 缓存为空值标记（避免穿透）
    String nullMarker = (String) redisTemplate.opsForValue().get("user:null:" + id);
    if (nullMarker != null) {
        return null;  // 之前已查出不存在
    }

    // 3. 查数据库
    user = userMapper.selectById(id);
    if (user != null) {
        redisTemplate.opsForValue().set("user:" + id, user, 1, TimeUnit.HOURS);
    } else {
        // 缓存空值，过期时间短一些
        redisTemplate.opsForValue().set("user:null:" + id, "1", 5, TimeUnit.MINUTES);
    }
    return user;
}

6.2 缓存击穿 ​

定义： 一个 热点 key 在缓存过期的瞬间，大量并发请求同时涌入，全部穿透到数据库。

危害： 高并发下瞬间打垮数据库。

解决方案：

方案一：互斥锁（Mutex Key） ​

只允许一个线程去数据库查询，其他线程等待。

java
public User getUserWithMutex(Long id) {
    String key = "user:" + id;
    String lockKey = "lock:" + key;

    // 1. 查缓存
    User user = (User) redisTemplate.opsForValue().get(key);
    if (user != null) {
        return user;
    }

    // 2. 获取互斥锁（SETNX）
    Boolean locked = redisTemplate.opsForValue()
        .setIfAbsent(lockKey, "1", 3, TimeUnit.SECONDS);

    if (Boolean.TRUE.equals(locked)) {
        try {
            // 双检——避免在等锁时另一个线程已重建缓存
            user = (User) redisTemplate.opsForValue().get(key);
            if (user != null) {
                return user;
            }

            // 3. 查数据库
            user = userMapper.selectById(id);
            if (user != null) {
                redisTemplate.opsForValue().set(key, user, 1, TimeUnit.HOURS);
            }
            return user;
        } finally {
            redisTemplate.delete(lockKey);  // 释放锁
        }
    } else {
        // 4. 没获取到锁，等待重试
        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        return getUserWithMutex(id);  // 递归重试
    }
}

方案二：逻辑过期 ​

思路： 缓存永不过期（物理上），但带上一个逻辑过期时间字段。查询时发现逻辑过期，异步重建缓存。

java
@Data
public class CacheData<T> {
    private T data;
    private long expireTime;  // 逻辑过期时间戳
}

public User getUserWithLogicalExpire(Long id) {
    String key = "user:" + id;

    // 1. 查缓存（缓存永不物理过期）
    CacheData<User> cacheData = (CacheData<User>) redisTemplate.opsForValue().get(key);

    if (cacheData == null) {
        // 缓存不存在，直接查库并设置
        return loadAndCache(id);
    }

    // 2. 判断逻辑是否过期
    if (cacheData.getExpireTime() > System.currentTimeMillis()) {
        // 未过期，直接返回
        return cacheData.getData();
    }

    // 3. 逻辑过期——尝试获取互斥锁，异步重建缓存
    String lockKey = "lock:" + key;
    Boolean locked = redisTemplate.opsForValue()
        .setIfAbsent(lockKey, "1", 3, TimeUnit.SECONDS);

    if (Boolean.TRUE.equals(locked)) {
        try {
            // 异步重建缓存
            CompletableFuture.runAsync(() -> {
                User freshUser = userMapper.selectById(id);
                CacheData<User> freshCache = new CacheData<>();
                freshCache.setData(freshUser);
                freshCache.setExpireTime(System.currentTimeMillis() + 3600_000);
                redisTemplate.opsForValue().set(key, freshCache);
            });
        } finally {
            redisTemplate.delete(lockKey);
        }
    }

    // 4. 返回过期数据（保证可用性）
    return cacheData.getData();
}

方案二：多级缓存 ​

引入本地缓存（Caffeine / Guava Cache）作为一级缓存，Redis 作为二级缓存，数据库作为三级存储。

java
@Component
public class MultiLevelCache {

    // 本地缓存（一级缓存）
    private final Cache<Long, User> localCache = Caffeine.newBuilder()
        .maximumSize(10000)             // 最大条目
        .expireAfterWrite(10, TimeUnit.MINUTES)  // 写入后 10 分钟过期
        .recordStats()                  // 监控统计
        .build();

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    public User getUser(Long id) {
        // 1. 一级缓存（本地）
        User user = localCache.getIfPresent(id);
        if (user != null) {
            return user;
        }

        // 2. 二级缓存（Redis）
        String key = "user:" + id;
        user = (User) redisTemplate.opsForValue().get(key);
        if (user != null) {
            localCache.put(id, user);  // 回填本地缓存
            return user;
        }

        // 3. 三级存储（数据库）
        user = userMapper.selectById(id);
        if (user != null) {
            redisTemplate.opsForValue().set(key, user, 30, TimeUnit.MINUTES);
            localCache.put(id, user);
        }
        return user;
    }
}

存在问题：

  1. 非重入 —— 同一线程不能再次获取已持有的锁
  2. 锁超时释放 —— 业务执行超时，锁被自动释放，导致其他线程获取到锁
  3. 释放问题 —— 可能释放其他线程的锁（需用唯一标识判断）
  4. 主从切换 —— 主节点挂了，从节点未同步锁信息，锁丢失

@Aspect
@Component
public class RedisLockAspect {

    @Autowired
    private RedissonClient redissonClient;

    @Around("@annotation(redisLock)")
    public Object around(ProceedingJoinPoint joinPoint, RedisLock redisLock)
            throws Throwable {
        // 解析 SPEL key
        String lockKey = parseKey(redisLock.key(), joinPoint);
        RLock lock = redissonClient.getLock(lockKey);

        boolean acquired = lock.tryLock(
            redisLock.waitTime(), redisLock.leaseTime(), redisLock.timeUnit());

        if (!acquired) {
            throw new RuntimeException("系统繁忙，请稍后重试");
        }

        try {
            return joinPoint.proceed();
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

        // 实现 SPEL 表达式解析
        return key;  // 简化
    }
}

过期删除机制：

Redis 采用 定期删除 + 惰性删除 结合策略。

定期删除 ​

每 100ms 运行一次，执行逻辑：

3. 删除其中已过期的 key
4. 如果超过 25% 的 key 已过期，重复步骤 2
5. 单次执行时间上限 25ms

11.2 接口限流（滑动窗口） ​

背景： 防止接口被恶意刷请求，控制单位时间内的访问次数。

基于 ZSet 的滑动窗口 ​

java
@Component
public class SlidingWindowRateLimiter {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * @param key       限流 key
     * @param windowMs  时间窗口（毫秒）
     * @param maxCount  最大请求次数
     * @return 是否允许通过
     */
    public boolean tryAcquire(String key, long windowMs, int maxCount) {
        long now = System.currentTimeMillis();
        String windowKey = "ratelimit:" + key;

        // 1. 移除窗口外的旧记录
        redisTemplate.opsForZSet()
            .removeRangeByScore(windowKey, 0, now - windowMs);

        // 2. 统计当前窗口内的请求数
        Long count = redisTemplate.opsForZSet()
            .zCard(windowKey);

        if (count != null && count >= maxCount) {
            return false;  // 限流
        }

        // 3. 记录本次请求
        redisTemplate.opsForZSet()
            .add(windowKey, String.valueOf(now), now);

        // 4. 设置过期时间（避免 key 长期占用内存）
        redisTemplate.expire(windowKey, windowMs * 2, TimeUnit.MILLISECONDS);

        return true;
    }
}

    public List<RankingVO> getTopN(int n) {
        Set<ZSetOperations.TypedTuple<Object>> set = 
            redisTemplate.opsForZSet()
                .reverseRangeWithScores(RANKING_KEY, 0, n - 1);

        List<RankingVO> list = new ArrayList<>();
        int rank = 1;
        for (ZSetOperations.TypedTuple<Object> tuple : set) {
            list.add(new RankingVO(
                Long.valueOf(tuple.getValue().toString()),
                tuple.getScore(),
                rank++
            ));
        }
        return list;

            .reverseRank(RANKING_KEY, String.valueOf(userId));
        Double score = redisTemplate.opsForZSet()
            .score(RANKING_KEY, String.valueOf(userId));
        if (rank == null) {
            return null;
        }
        return new RankingVO(userId, score, rank + 1);

            .unionAndStore("ranking:weekly", List.of(weekKeys), "ranking:weekly");

    }

            redisTemplate.opsForZSet()
                .reverseRangeWithScores(RANKING_KEY, 0, n - 1);

        List<RankingVO> list = new ArrayList<>();
        int rank = 1;
        for (ZSetOperations.TypedTuple<Object> tuple : set) {
            list.add(new RankingVO(
                Long.valueOf(tuple.getValue().toString()),
                tuple.getScore(),
                rank++
            ));
        }
        return list;
    }

            .reverseRank(RANKING_KEY, String.valueOf(userId));
        Double score = redisTemplate.opsForZSet()
            .score(RANKING_KEY, String.valueOf(userId));
        if (rank == null) {
            return null;
        }

            stringRedisTemplate.opsForStream()
                .createGroup(STREAM_KEY, GROUP_NAME);
        } catch (Exception e) {
            // 可能已存在
        }
    }

    // 发送消息
    public RecordId send(Map<String, String> body) {
        return stringRedisTemplate.opsForStream()
            .add(StreamRecords.newRecord()
                .ofMap(body)
                .withStreamKey(STREAM_KEY));
    }

    // 消费消息（定时任务调用）
    @Scheduled(fixedDelay = 100)
    public void consume() {
        List<MapRecord<String, String, String>> records = 
            stringRedisTemplate.opsForStream()
                .read(Consumer.from(GROUP_NAME, "consumer-1"),
                      StreamReadOptions.empty().count(10).block(Duration.ofMillis(500)),
                      StreamOffset.create(STREAM_KEY, ReadOffset.lastConsumed(GROUP_NAME)));

        for (MapRecord<String, String, String> record : records) {
            try {
                String orderId = record.getValue().get("orderId");
                processOrder(orderId);
                // ACK
                stringRedisTemplate.opsForStream()
                    .acknowledge(STREAM_KEY, GROUP_NAME, record.getId());
            } catch (Exception e) {
                log.error("处理消息失败: {}", record.getId(), e);
            }
        }
    }

        // 1. 去重（每人限购一件）
        String userKey = "flash:user:" + activityId + ":" + skuId;
        Boolean added = redisTemplate.opsForSet()
            .add(userKey, String.valueOf(userId));

            .decrement(stockKey);
        if (stock < 0) {
            // 库存不足，回滚
            redisTemplate.opsForValue().increment(stockKey);
            redisTemplate.opsForSet().remove(userKey, String.valueOf(userId));
            return false;
        }

        // 3. 异步落单（发送到消息队列）
        sendOrderMessage(activityId, skuId, userId);

        return true;
    }

    public boolean flashSaleWithLua(Long activityId, Long skuId, Long userId) {
        String luaScript = """
            local userKey = KEYS[1]
            local stockKey = KEYS[2]
            local userId = ARGV[1]
            
            -- 检查是否已购买
            local exists = redis.call('SISMEMBER', userKey, userId)
            if exists == 1 then
                return 0  -- 已购买
            end

            local stock = redis.call('DECR', stockKey)
            if stock < 0 then
                redis.call('INCR', stockKey)
                return 0  -- 库存不足
            end
            
            -- 记录用户
            redis.call('SADD', userKey, userId)
            return 1  -- 抢购成功

            "flash:user:" + activityId + ":" + skuId,
            "stock:" + activityId + ":" + skuId
        ), String.valueOf(userId));

        if (result != null && result == 1) {
            sendOrderMessage(activityId, skuId, userId);
            return true;
        }
        return false;

避免 O(N) 命令KEYS、SMEMBERS 等慎用（生产用 SCAN）
合理设置过期避免 key 永久占用内存
连接池配置按业务峰值合理设置连接池大小
使用 Pipeline批量操作时性能提升显著
