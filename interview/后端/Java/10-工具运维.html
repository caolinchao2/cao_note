工具 & 运维 ​

常问等级：★★★ 高频必考 / ★★☆ 中频常见 / ★☆☆ 低频了解 深度标准：每个考点讲清「是什么 → 为什么 → 追问应对 → 易错点」。

Git 常用命令、merge 与 rebase 区别 ★★☆ ​

常用命令 ​

  • git init / clone / add / commit / push / pull / fetch / status / log / diff / branch / checkout / switch / merge / rebase / reset / revert / stash / tag。

merge vs rebase ​

  • merge：保留分支历史，生成一个新的 merge commit，历史是「合并」的分叉结构。
  • rebase：把当前分支的提交「变基」到目标分支上，历史线性、干净，但改写提交历史（不适合已推送共享的分支）。

追问应对 ​

  • 「merge 和 rebase 怎么选？」→ 公共分支用 merge（保留历史、安全），个人 feature 分支用 rebase 保持整洁。
  • 「reset 和 revert 区别？」→ reset 回退（移动 HEAD，可能丢提交）；revert 生成反向提交（保留历史，安全）。

Maven 依赖冲突 ★★☆ ​

为什么冲突 ​

  • 传递依赖：A 依赖 B(1.0)，C 依赖 B(2.0)，同时引入 A、C 导致 B 版本冲突。

解决 ​

  • 最短路径优先、最先声明优先（Maven 默认原则）。
  • 用 <exclusion> 排除某个传递依赖。
  • dependencyManagement 统一管理版本。
  • mvn dependency:tree 查看依赖树定位冲突。

追问应对 ​

  • 「怎么定位依赖冲突？」→ mvn dependency:tree 看依赖树，找出冲突版本。

Docker 基础概念 ★★☆ ​

核心概念 ​

  • 镜像（Image）：只读模板，分层构建。
  • 容器（Container）：镜像运行实例，隔离但共享宿主机内核。
  • Dockerfile：构建镜像的脚本。
  • 仓库（Registry）：存镜像（Docker Hub / 私有 Harbor）。

常用命令 ​

  • docker build / run / ps / images / exec / logs / stop / rm / rmi / pull / push。
  • docker run -d -p 8080:80 -v 宿主:容器 -e 环境变量 镜像。

与虚拟机区别 ​

  • 虚拟机虚拟完整 OS（重、慢、隔离彻底）；容器共享内核（轻、快、秒级启动、隔离较弱）。

追问应对 ​

  • 「镜像分层的好处？」→ 复用公共层、构建快、传输省空间。
  • 「容器和镜像关系？」→ 镜像 + 可写层 = 容器；容器可 commit 成镜像。

Linux 常用命令：进程、日志、端口、内存 CPU ★★★ ​

进程 ​

  • ps -ef | grep xxx、top（实时）、kill -9 pid、nohup ... &。

日志 ​

  • tail -f xxx.log、tail -n 100、grep '关键字' xxx.log、less。

端口与网络 ​

  • netstat -tlnp、ss -tlnp（看监听端口）、lsof -i:8080。

内存 CPU ​

  • free -h（内存）、top/htop（CPU/内存）、df -h（磁盘）、du -sh *（目录大小）。

文件操作 ​

  • cat/less/head/tail（查看）、find（查找文件）、chmod/chown（权限）、tar -zxvf（解压）。

追问应对 ​

  • 「CPU 飙高怎么查？」→ top 找进程 → top -Hp 找线程 → jstack 定位代码（配合 Java 进程）。

常见安全：XSS、CSRF、SQL 注入 ★★★ ​

SQL 注入 ​

  • 原理：拼接 SQL 让用户输入变成 SQL 逻辑（' OR '1'='1）。
  • 防御：预编译（PreparedStatement/#{}）、参数校验、最小权限、ORM。

XSS（跨站脚本） ​

  • 原理：注入恶意脚本到页面，窃取 cookie 等。
  • 类型：存储型、反射型、DOM 型。
  • 防御：输出转义、CSP、HttpOnly cookie、输入过滤。

CSRF（跨站请求伪造） ​

  • 原理：诱导用户在已登录状态访问恶意链接，冒用身份发请求。
  • 防御：CSRF Token、SameSite cookie、验证 Referer、验证码。

追问应对 ​

  • 「XSS 和 CSRF 区别？」→ XSS 利用信任「用户」注入脚本；CSRF 利用信任「浏览器/登录态」冒用身份。
  • 「密码怎么存？」→ 加盐哈希（BCrypt/Argon2），不能明文、不能只 MD5。

越权漏洞（IDOR）★★★ ​

  • 水平越权：访问同级别他人数据（A 用户访问 B 用户订单，改 URL 的 id）。
  • 垂直越权：低权限访问高权限功能。
  • 防御：服务端鉴权（不能只前端隐藏按钮）、资源归属校验（查询时带 user_id 校验）、角色权限控制。

追问应对 ​

  • 「前端隐藏了按钮就安全吗？」→ 不安全，接口要服务端做权限校验。

线上排查完整流程 ★★★ ​

  1. 确认现象：报错信息、影响范围、是否可复现。
  2. 看监控：CPU、内存、GC、慢查询、接口耗时、错误率。
  3. 看日志：应用日志、错误堆栈、慢 SQL 日志。
  4. 定位：
    • CPU 高 → top + jstack。
    • 内存高/OOM → jmap dump + MAT 分析。
    • 响应慢 → 慢 SQL、下游依赖、GC 频繁。
    • 报错 → 堆栈定位代码。
  5. 修复 + 验证 + 复盘（加监控告警、补测试）。

追问应对 ​

  • 「接口超时怎么排查？」→ 看是否慢 SQL、下游服务慢、GC、网络；用链路追踪（traceId）定位耗时环节。

线程 dump 分析 ★★☆ ​

  • 用途：分析线程状态、定位死锁、CPU 高、锁竞争。
  • jstack pid > dump.txt；关注 BLOCKED（等锁）、WAITING、RUNNABLE 状态，找死锁输出。

追问应对 ​

  • 「jstack 看到大量 BLOCKED 说明什么？」→ 锁竞争严重，找持有锁的线程和锁对象。

JVM 调优参数 ★★☆ ​

  • 见 JVM 篇：-Xms/-Xmx/-Xmn、-XX:MetaspaceSize、-XX:+UseG1GC、-XX:MaxGCPauseMillis、OOM dump 等。

日志框架与监控体系 ★★☆ ​

日志 ​

  • SLF4J + Logback/Log4j2；日志级别 TRACE/DEBUG/INFO/WARN/ERROR。
  • 结构化日志（JSON）、traceId 贯穿、避免打印敏感信息。

监控 ​

  • 指标：Prometheus + Grafana；链路：SkyWalking/Zipkin；日志：ELK。
  • 告警：CPU/内存/错误率/慢接口阈值告警。

追问应对 ​

  • 「为什么用 SLF4J？」→ 门面模式，统一日志接口，底层实现可替换。

如果程序员删库跑路了，怎么恢复数据 ★★★ ​

思路（核心：备份 + binlog 恢复 + 预防） ​

  1. 第一时间止损：立即停掉相关写入、锁定数据库访问，防止数据被继续覆盖/污染。
  2. 恢复顺序：先找「最近的全量备份」，恢复到备份时间点，再用 binlog 增量回放到删库之前。
  3. binlog 恢复：
    • binlog 记录了所有写操作，定位到「删库操作」之前的 position，用 mysqlbinlog 回放。
    • 删除 drop/delete 的操作要过滤掉，只回放到删库前一刻。
  4. 主从恢复：如果还有从库没被同步删除（从库延迟或有只读从库），可直接从从库捞数据。

预防（更关键） ​

  • 定期全量备份 + binlog 开启（log_bin=ON）+ 异地备份。
  • 主从复制 + 延迟从库（延迟复制，防止误删立即同步）。
  • 权限最小化：生产库不给普通开发 drop 权限，用变更审批。
  • 删除操作做软删除（逻辑删除）而非物理 drop。
  • 备份演练：定期验证备份可恢复（很多「有备份」却「恢复不了」）。

追问应对 ​

  • 「binlog 恢复的原理？」→ binlog 记录逻辑变更，按时间点/position 回放，重演删库之前的写入。
  • 「延迟从库有什么用？」→ 主库误删后，延迟从库还没同步删除，能作为数据救命的副本。

删除数据的几种恢复手段 ★★☆ ​

  • 物理备份恢复：全量备份（mysqldump / XtraBackup）+ binlog 增量回放。
  • 延迟从库：从库故意延迟同步，主库误操作时从库仍有旧数据。
  • 闪回（Flashback）：把 binlog 里的 delete/update 反向解析成 insert/update 还原（如 MyFlash、binlog2sql）。
  • 回收站机制：数据库开启回收站，drop table 先移入回收站可恢复（部分云数据库支持）。

追问应对 ​

  • 「闪回原理？」→ 解析 binlog，把删除/更新操作反转为插入/更新，逆向还原数据。

在线调试工具 Arthas 怎么用 ★★☆ ​

是什么 ​

  • 阿里开源的 Java 在线诊断工具，无需重启、无需改代码，attach 到运行中的 JVM 做排查。

启动 ​

  • java -jar arthas-boot.jar，选择要诊断的 Java 进程，进入 Arthas 命令行。

常用命令 ​

  • dashboard：实时看线程、内存、GC、CPU 概览。
  • thread：查看线程状态；thread -n 3 看最忙的 3 个线程；thread --state BLOCKED 找阻塞线程；thread -b 直接找出死锁线程。
  • watch 类名 方法名 '{params, returnObj, throwExp}'：观察方法入参、返回值、异常（-x 3 展开深度）。
  • trace 类名 方法名：追踪方法调用耗时，定位性能瓶颈。
  • jad 类全限定名：反编译 class，确认线上跑的代码版本。
  • sc 查看类加载信息，sm 查看方法，ognl 执行表达式，redefine 热更新 class。
  • tt（Time Tunnel）：记录方法调用，可回放。

典型场景 ​

  • CPU 高：thread -n 3 找热点线程 → 对应方法栈。
  • 接口慢：trace 找耗时方法。
  • 怀疑代码没生效：jad 反编译确认线上代码。
  • 看方法入参/异常：watch。

追问应对 ​

  • 「Arthas 和 jstack/jmap 区别？」→ jstack/jmap 是 JDK 自带、功能单一；Arthas 更强大，支持在线 watch/trace/jad/redefine，交互式诊断。
