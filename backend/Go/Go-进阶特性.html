Go 进阶特性 ​

指针与值语义、接口、错误处理、反射、泛型与测试，构建 Java / Python 工程师的 Go 中阶能力。

一、指针与值语义 ​

1.1 指针是什么：& 与 * ​

Go 有指针，但没有 C 的指针算术（不能 p++ 移动指针）。指针保存变量内存地址，& 取地址，* 解引用：

go
func main() {
    n := 42
    p := &n        // p 是 *int，指向 n
    fmt.Println(*p) // 42，解引用取值
    *p = 100        // 通过指针修改原变量
    fmt.Println(n)  // 100
}
func main() {
    n := 42
    p := &n        // p 是 *int，指向 n
    fmt.Println(*p) // 42，解引用取值
    *p = 100        // 通过指针修改原变量
    fmt.Println(n)  // 100
}

1.2 值传递与"引用类型"辨析 ​

Go 的传参一律是值拷贝（Java 同规则）。但 slice / map / channel / 函数 / 接口内部本就持有指向底层数据的引用，因此函数内修改"看起来像引用传递"：

go
func addOne(m map[string]int) { m["a"]++ } // 生效：map 头是引用
func addOneS(s []int) { s[0]++ }           // 生效：修改的是共享底层数组
func appendS(s []int) { s = append(s, 9) } // 不生效：len/cap 是拷贝，扩容后更是新数组
func addOne(m map[string]int) { m["a"]++ } // 生效：map 头是引用

func appendS(s []int) { s = append(s, 9) } // 不生效：len/cap 是拷贝，扩容后更是新数组

1.3 何时该用指针 ​

场景用指针原因

二、struct 方法与 receiver ​

2.1 方法与 receiver ​

方法 = 函数 + 接收者（receiver）。接收者写在 func 与函数名之间：

go
type Rectangle struct{ W, H float64 }

// 值 receiver：操作的是副本
func (r Rectangle) Area() float64 { return r.W * r.H }

// 指针 receiver：可修改原对象
func (r *Rectangle) Scale(f float64) { r.W *= f; r.H *= f }

func main() {
    rc := Rectangle{W: 3, H: 4}
    fmt.Println(rc.Area()) // 12
    rc.Scale(2)
    fmt.Println(rc.W)      // 6
}
type Rectangle struct{ W, H float64 }

// 值 receiver：操作的是副本

2.2 值 receiver 与指针 receiver 的取舍 ​

  • 需要修改对象、或对象含需要共享的状态（如互斥锁、大切片）时，统一用指针 receiver。
  • 类型是 map / slice / 小型值类型，或期望不可变语义时用值 receiver。
  • 关键约束：同一类型的所有方法，receiver 类型应保持一致。若既有值又有指针方法，其方法集割裂会引发"对象是否实现接口"的困惑（见 2.4）。
  • 变更成本：receiver 从值改指针会破坏所有调用的接口满足性，接口设计期就应定好。

2.3 nil receiver 处理 ​

指针方法被 nil 接收者调用是合法的（只要方法内部不访问其字段）：

go
type Config struct{ Timeout int }

func (c *Config) GetTimeout() int {
    if c == nil { // nil 保护，让零值也可用
        return 30
    }
    return c.Timeout
}

var c *Config
fmt.Println(c.GetTimeout()) // 30

func (c *Config) GetTimeout() int {

2.4 方法集与接口 ​

Receiver值类型 T 的方法集指针类型 *T 的方法集
值方法 func (t T) M()含 M含 M
指针方法 func (t *T) M()不含 M含 M

值类型 T 只拥有值方法；只有 *T 才拥有全部方法。这导致：var _ Interface = T{} 若 Interface 声明了指针方法会编译失败。因此实现接口的统一写法是传指针：var _ Handler = &HandlerImpl{}。

三、interface 与类型系统 ​

3.1 接口定义与鸭子类型 ​

Go 接口是方法的集合，实现是隐式的：只要类型具备接口要求的全部方法，就自动满足该接口，无需 implements 关键字。类型实现接口不需要 import 接口所在包（Java 则必须），因此第三方库类型天然可以补实现本地接口。

go
type Stringer interface {
    String() string
}

type Point struct{ X, Y int }

func (p Point) String() string { return fmt.Sprintf("(%d,%d)", p.X, p.Y) }

func printAny(s Stringer) { fmt.Println(s.String()) }
// Point 自动满足 Stringer，可传入 printAny
type Stringer interface {
    String() string
}

3.4 interface 的两个经典陷阱 ​

陷阱一：接口为 nil 但内部指针非 nil。

go
var err error
var p *MyErr = nil
err = p        // 把 nil 指针装进接口，接口不为 nil！
if err != nil { // 永远为 true，判空失效
    fmt.Println("有错误") // 必走这里
}
var err error
var p *MyErr = nil
err = p        // 把 nil 指针装进接口，接口不为 nil！
if err != nil { // 永远为 true，判空失效
    fmt.Println("有错误") // 必走这里
}

原因：接口由 (type, value) 二元组构成，p 的 type 非空所以接口非 nil。判断返回值前先显式 if p == nil { return nil }。

陷阱二：大接口难以实现与 mock。 只声明自己需要的最小方法集（见 3.5）。

3.5 接口设计原则：小接口 ​

  • 接口属于消费者：在需要接口的地方声明，而不是"先定义一堆接口再实现"。
  • 接受接口，返回结构体（Accept interfaces, return structs）。
  • 依赖倒置常用自查断言：var _ Repository = (*MysqlRepo)(nil)，编译期验证实现完整性。
  • 标准库榜样：io.Reader、io.Writer 都只有一个方法。

4.5 panic 与 recover ​

panic 用于"不可恢复的错误"（数组越界、断言失败、显式 panic），等价 Java RuntimeException 中不打算 catch 的那一类：

go
func safe(f func()) (err error) {
    defer func() { // recover 必须在 defer 中执行才生效
        if r := recover(); r != nil {
            err = fmt.Errorf("panic: %v", r)
        }
    }()
    f()
    return nil
}

func main() {
    if err := safe(func() { panic("boom") }); err != nil {
        fmt.Println("已恢复:", err)
    }
}

五、反射 reflect ​

5.1 反射三法则 ​

Go 反射基于 reflect.Value 与 reflect.Type 两个核心类型，三条法则：

  1. 接口值可反射成反射对象：t := reflect.TypeOf(x)、v := reflect.ValueOf(x)。
  2. 反射对象可还原为接口值：v.Interface()。
  3. 要修改反射对象，其值必须可设置（settable），即来自指针：reflect.ValueOf(&x).Elem()。
go
type User struct {
    Name string `validate:"required"`
    Age  int    `validate:"gte=0"`
}

func main() {
    u := User{}
    vt := reflect.TypeOf(u)
    for i := 0; i < vt.NumField(); i++ {
        f := vt.Field(i)
        fmt.Println(f.Name, "tag:", f.Tag.Get("validate"))
    }
}

5.2 典型用途：写一个迷你校验器 ​

go
func Validate(x any) error {
    v := reflect.ValueOf(x)
    t := v.Type()
    for i := 0; i < v.NumField(); i++ {
        tag := t.Field(i).Tag.Get("validate")
        switch tag {
        case "required":
            if v.Field(i).IsZero() {
                return fmt.Errorf("字段 %s 必填", t.Field(i).Name)
            }
        case "gt=0":
            if v.Field(i).Int() <= 0 {
                return fmt.Errorf("字段 %s 必须大于 0", t.Field(i).Name)
            }
        }
    }
    return nil

5.3 反射的代价与替代 ​

  • 性能：反射调用比直接调用慢一到两个数量级，热点路径不要用。
  • 可读性：牺牲静态类型安全，能编译过不代表逻辑对。
  • 替代：优先用泛型（编译期解决）、代码生成（stringer / mockgen）、或明确的小接口设计，反射留作最后手段。标准库自身（json、fmt）重度使用反射，这是合理场景。

6.4 泛型限制（相比 Java / C#） ​

  • 不支持泛型方法（方法不能额外声明类型参数），只能泛型类型 + 泛型函数。
  • 无协变/逆变，[]T 不能赋给 []any。
  • 类型推断能力有限，复杂场景需显式写类型参数。
  • 实参不支持类型参数本身的方法约束之外的运算（需要约束接口显式声明）。

Java 开发者视角：Go 泛型是"语法糖级"的实现，无法覆盖 Java 泛型容器的全部场景；官方建议优先"碰巧能用"，不要为抽象而抽象。

Go 的时间格式是参考时间 2006-01-02 15:04:05.999999999 -0700 MST（1月2日 3点4分5秒 06年 -7时区），每个数字都是固定语义。常用常量：time.RFC3339（2006-01-02T15:04:05Z07:00，JSON 默认输出格式）。存储与传输统一用 UTC，展示时转本地时区（见实践篇时区坑）。
