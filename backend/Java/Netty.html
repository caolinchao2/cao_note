Netty ​

高性能网络编程框架，异步事件驱动的 NIO 框架。Netty 由 JBoss 提供，现为独立开源项目，广泛应用于互联网、大数据、游戏、通信等领域。

一、Netty 概述 ​

1.1 什么是 Netty ​

Netty 是一个异步、事件驱动的网络编程框架，它基于 Java NIO 构建，极大地简化了 TCP、UDP、HTTP、WebSocket 等协议的开发工作。

核心特性：

  • 异步非阻塞：所有 I/O 操作都是异步的，通过 Future / Callback 机制获取结果。
  • 事件驱动：将网络事件（连接建立、数据读取、异常发生等）抽象为事件，交由 Handler 处理。
  • 高性能：基于 Reactor 模型、零拷贝、池化内存等机制实现高吞吐、低延迟。
  • 易用性：API 简洁，开箱即用的编解码器，屏蔽了 Java NIO 的复杂性。

1.2 Netty vs Java NIO ​

对比维度Java NIONetty
API 复杂度直接操作 ByteBuffer、Selector、Channel，代码量大高度抽象，Handler 链式处理，代码简洁
开发效率需要手动处理粘包拆包、断线重连等内置各种编解码器和工具类
性能基础 NIO，无池化、零拷贝等优化池化内存、零拷贝、I/O 多路复用优化
可靠性需要自行处理异常重连等支持空闲检测、写缓冲区水位、流量控制
扩展性需自行实现线程模型灵活的事件循环组和 Handler 编排
社区生态无Dubbo、Spring Cloud Gateway、Elasticsearch、RocketMQ 等均基于 Netty

1.3 使用场景 ​

  • RPC 框架底层通信：Dubbo、gRPC、Thrift 的传输层
  • API 网关：Spring Cloud Gateway、Zuul 2.x
  • 即时通讯（IM）：微信、钉钉等服务端消息推送
  • 游戏服务器：MMORPG、棋牌游戏的高并发连接管理
  • 消息推送系统：WebSocket 推送、SSE
  • 大数据组件：HBase、Flink、Spark 的部分通信模块
  • 消息队列：RocketMQ、Kafka 的部分网络层

二、Reactor 模式 ​

2.1 Reactor 为什么是 Netty 的基础 ​

Reactor 是一种事件驱动的设计模式，它将 I/O 事件分发到对应的处理器。Netty 的线程模型正是基于 Reactor 模式的变体实现的。

Reactor 模式的核心角色：

  • Reactor：负责监听和分发事件
  • Acceptor：处理新的连接请求
  • Handler：处理具体的业务逻辑

2.2 单线程 Reactor（单 Reactor 单线程） ​

所有 I/O 操作（包括 accept、read、write）都在同一个线程中完成。

EventLoopGroup 是一个线程池，管理多个 EventLoop 实例。

  • 一个 EventLoop 对应一个线程，负责多个 Channel 的 I/O 事件
  • EventLoop 与 Channel 是 多对一 的关系：一个 EventLoop 可管理多个 Channel
  • EventLoop 内部维护着一个 Selector，用于监听 Channel 的状态变化

3.4 ChannelPipeline / ChannelHandlerContext ​

ChannelPipeline 是一个 Handler 链，负责管理 ChannelHandler 的执行顺序。

  • pipeline.addLast(handler)：在链尾添加 Handler
  • pipeline.addFirst(handler)：在链头添加 Handler
  • pipeline.remove(handler)：移除 Handler

ChannelHandlerContext 代表 Pipeline 中的一个节点，用于在 Handler 间传递数据：

java
// 通过 ChannelHandlerContext 转发事件
ctx.fireChannelRead(msg);     // 将消息传递给下一个 Inbound Handler
ctx.write(msg);                // 将消息写入下一个 Outbound Handler
ctx.channel().write(msg);     // 从 Pipeline 尾部开始寻找 Outbound Handler
// 通过 ChannelHandlerContext 转发事件

五、ChannelHandler（重点） ​

5.1 ChannelInboundHandler / ChannelOutboundHandler ​

InboundHandler：处理入站事件

java
public class MyInboundHandler extends ChannelInboundHandlerAdapter {

    @Override
    public void channelRegistered(ChannelHandlerContext ctx) {
        System.out.println("Channel 注册到 EventLoop");
        ctx.fireChannelRegistered();
    }

    @Override
    public void channelActive(ChannelHandlerContext ctx) {
        System.out.println("Channel 已激活（连接建立）");
        ctx.fireChannelActive();
    }

    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        System.out.println("收到数据：" + msg);
        // 处理业务后，传递给下一个 Handler
        ctx.fireChannelRead(msg);
    }

    @Override
    public void channelReadComplete(ChannelHandlerContext ctx) {
        System.out.println("读取完成");
        ctx.flush();
    }

    @Override
    public void exceptionCaught(ChannelHandlerContext ctx, Throwable cause) {
        cause.printStackTrace();
        ctx.close();
    }

    @Override
    public void channelInactive(ChannelHandlerContext ctx) {
        System.out.println("连接关闭");
        ctx.fireChannelInactive();
    }
}

6.4 TCP 粘包 / 拆包问题及解决方案 ​

问题现象：

  • 粘包：发送方发送 ABC 和 DEF，接收方收到 ABCDEF

8.1 EventLoop 与线程模型 ​

Netty 的线程模型核心思想：

  1. 一个 EventLoop 绑定一个线程，在其生命周期内不会变更
  2. 一个 Channel 在生命周期内只注册到一个 EventLoop，保证线程安全
  3. 一个 EventLoop 可管理多个 Channel，提升线程利用率
  4. EventLoop 内部维护了一个 Selector，循环处理 I/O 事件
EventLoopGroup（线程池）
   │
   ├── EventLoop-1（线程1）── Channel A, Channel B, Channel C
   ├── EventLoop-2（线程2）── Channel D, Channel E
   └── EventLoop-3（线程3）── Channel F, Channel G, Channel H, Channel I
EventLoopGroup（线程池）
   │
   ├── EventLoop-1（线程1）── Channel A, Channel B, Channel C
   ├── EventLoop-2（线程2）── Channel D, Channel E
   └── EventLoop-3（线程3）── Channel F, Channel G, Channel H, Channel I

线程模型的优势：

// Dubbo 解码器简化示意
public class DubboDecoder extends LengthFieldBasedFrameDecoder {

    public DubboDecoder() {
        super(8 * 1024 * 1024,   // 最大帧长度 8MB
              12,                // 长度字段偏移
              4,                 // 长度字段长度
              0,                 // 长度调整
              16);               // 剥离头部长度
    }

    @Override
    protected Object decode(ChannelHandlerContext ctx, ByteBuf in) {
        ByteBuf frame = (ByteBuf) super.decode(ctx, in);
        if (frame == null) return null;

        // 解析 Dubbo 协议头
        short magic = frame.readShort();        // 魔数
        byte serializationId = frame.readByte(); // 序列化方式
        long requestId = frame.readLong();       // 请求 ID
        int bodyLength = frame.readInt();        // 消息体长度

        // 反序列化 body
        byte[] body = new byte[bodyLength];
        frame.readBytes(body);
        return deserialize(body, serializationId);
    }
}
