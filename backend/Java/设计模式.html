设计模式 ​

GoF 23 种设计模式在 Java 中的经典实现。

设计模式（Design Pattern）是一套被反复使用、多数人知晓、经过分类编目的代码设计经验的总结。使用设计模式是为了可重用代码、让代码更容易被他人理解、保证代码可靠性。

一、设计模式概述 ​

1.1 什么是设计模式 ​

设计模式描述了在软件设计过程中针对特定场景的、可重复使用的解决方案。1995 年，GoF（Gang of Four，四人组）出版了《Design Patterns: Elements of Reusable Object-Oriented Software》，定义了 23 种经典设计模式。

1.2 模式的分类 ​

设计模式按目的分为三大类：

类别关注点包含模式
创建型模式对象的创建过程单例、工厂方法、抽象工厂、建造者、原型
结构型模式类和对象的组合代理、适配器、装饰器、外观、组合、桥接、享元
行为型模式对象之间的通信策略、模板方法、观察者、责任链、命令、状态、迭代器、访问者、中介者、备忘录、解释器

1.3 六大设计原则（SOLID + 最少知识原则） ​

在设计模式中，面向对象设计原则是基石。以下是六个核心原则：

缩写原则名称核心思想
S单一职责原则（SRP）一个类只有一个引起它变化的原因
O开闭原则（OCP）对扩展开放，对修改关闭
L里氏替换原则（LSP）子类必须能替换父类
I接口隔离原则（ISP）接口应该小而专，不强迫依赖不需要的方法
D依赖倒置原则（DIP）面向接口编程，不依赖具体实现
LoD最少知识原则（迪米特法则）一个对象应尽可能少地了解其他对象

二、创建型模式（Creational Patterns） ​

创建型模式关注对象的创建机制，将对象的创建与使用分离，使系统在创建对象时更加灵活。

2.1 单例模式（Singleton Pattern） ​

定义：确保一个类只有一个实例，并提供一个全局访问点。

单例模式是 Java 中使用最广泛的设计模式之一，也是面试考查的重点。

2.1.3 DCL（双重检查锁，Double-Checked Locking） ​

java
public class SingletonDCL {
    private static volatile SingletonDCL instance;

    private SingletonDCL() {}

    public static SingletonDCL getInstance() {
        if (instance == null) {                // 第一次检查
            synchronized (SingletonDCL.class) {
                if (instance == null) {        // 第二次检查
                    instance = new SingletonDCL();
                }
            }
        }
        return instance;
    }
}

2.1.7 Spring Bean 中的单例 ​

Spring 容器中 Bean 的默认作用域为 singleton，但 Spring 的单例与 GoF 的单例不同：

  • Scope 为 singleton：每个 Spring IoC 容器中只有一个 Bean 实例
  • 底层实现：Spring 通过容器级别的 Map 缓存来保证单例，而非通过类的静态属性
  • 同一个类可以在 Spring 容器中被多次声明为不同的 Bean
java
@Component
@Scope("singleton") // 默认就是 singleton
public class MyService {
    // Spring 容器中只有这个 Bean 的一个实例
}

2.3 建造者模式（Builder Pattern） ​

定义：将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示。

java
public class Computer {
    private String cpu;
    private String ram;
    private String storage;
    private boolean hasBluetooth;
    private boolean hasWifi;

    private Computer(Builder builder) {
        this.cpu = builder.cpu;
        this.ram = builder.ram;
        this.storage = builder.storage;
        this.hasBluetooth = builder.hasBluetooth;
        this.hasWifi = builder.hasWifi;
    }

    // 静态内部 Builder 类
    public static class Builder {
        private String cpu;
        private String ram;
        private String storage;
        private boolean hasBluetooth;
        private boolean hasWifi;

        public Builder cpu(String cpu) { this.cpu = cpu; return this; }
        public Builder ram(String ram) { this.ram = ram; return this; }
        public Builder storage(String storage) { this.storage = storage; return this; }
        public Builder bluetooth(boolean hasBluetooth) { this.hasBluetooth = hasBluetooth; return this; }
        public Builder wifi(boolean hasWifi) { this.hasWifi = hasWifi; return this; }

        public Computer build() {
            return new Computer(this);
        }
    }
}

2.4 原型模式（Prototype Pattern） ​

定义：通过复制已有对象来创建新对象，而不是通过 new 创建。

java
public class Prototype implements Cloneable {
    private String name;
    private List<String> tags;

    public Prototype(String name, List<String> tags) {
        this.name = name;
        this.tags = tags;
    }

3.1.3 CGLIB 动态代理 ​

import net.sf.cglib.proxy.Enhancer;
import net.sf.cglib.proxy.MethodInterceptor;
import net.sf.cglib.proxy.MethodProxy;
import java.lang.reflect.Method;

public class CglibProxyInterceptor implements MethodInterceptor {
    private Object target;

    public CglibProxyInterceptor(Object target) {
        this.target = target;
    }

    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        System.out.println("CGLIB 动态代理 - 前置处理");
        Object result = proxy.invoke(target, args); // 调用目标对象

        return (T) enhancer.create();

3.5 组合模式（Composite Pattern） ​

定义：将对象组合成树形结构以表示"部分-整体"的层次结构，使客户端对单个对象和组合对象的使用具有一致性。

// 抽象组件
public interface FileComponent {
    void show();
    long getSize();
}

// 叶子节点：文件
public class FileLeaf implements FileComponent {
    private String name;
    private long size;

    public FileLeaf(String name, long size) {
        this.name = name;
        this.size = size;
    }

    public void show() { System.out.println("文件: " + name); }
    public long getSize() { return size; }
}

// 组合节点：文件夹
public class FolderComposite implements FileComponent {
    private String name;
    private List<FileComponent> children = new ArrayList<>();

    public FolderComposite(String name) { this.name = name; }

    public void add(FileComponent component) { children.add(component); }
    public void remove(FileComponent component) { children.remove(component); }

    public void show() {
        System.out.println("文件夹: " + name);
        for (FileComponent child : children) {
            child.show();
        }
    }

    public long getSize() {
        long total = 0;
        for (FileComponent child : children) {
            total += child.getSize();
        }
        return total;
    }
}

6.1 设计模式选择指南 ​

需求场景推荐模式
需要全局唯一实例单例模式
需要灵活创建对象工厂方法 / 抽象工厂
对象构建过程复杂建造者模式
需要大量相似对象原型模式（克隆）
需要控制对象访问代理模式
接口不兼容需要转换适配器模式
需要动态添加功能装饰器模式
简化复杂子系统访问外观模式
处理树形层次结构组合模式
抽象与实现需要独立变化桥接模式
共享大量细粒度对象享元模式
算法需要动态切换策略模式
算法骨架固定、步骤可变模板方法模式
一对多依赖通知观察者模式
请求需要多级处理责任链模式
请求需要排队/撤销命令模式
对象行为依赖其状态状态模式
需统一遍历集合元素迭代器模式
需在不改元素类的前提下增加操作访问者模式
多对象交互需解耦中介者模式
需要保存和恢复对象状态备忘录模式
需要解释自定义语言解释器模式

6.2 核心要点 ​

  • 设计原则优先于设计模式：不要为了用模式而用模式，遵循 SOLID 原则往往比套用模式更重要
  • 组合优于继承：大多数设计模式都强调使用组合而非继承来复用代码
  • 面向接口编程：将抽象与实现分离，降低耦合
  • 开闭原则是核心：对扩展开放、对修改关闭是所有设计模式的共同追求
  • 模式是工具不是教条：根据实际场景灵活应用，可以变体、组合使用多种模式
