Arthas 概述 ​

什么是 Arthas ​

Arthas 是 Alibaba 开源的 Java 诊断工具，主要解决以下痛点：

  • 线上代码是否真的发布了预期版本？
  • 某个接口为什么响应慢？慢在哪里？
  • 如何在不重启的情况下修改线上代码？
  • 线上 JVM 内存暴涨，如何快速定位？
  • 为什么 CPU 突然飙升到 100%？

Arthas 基于 Java Agent 机制，通过字节码增强技术动态附加到目标 JVM 进程上，支持 JDK 6+，对业务代码零侵入。

与传统排查方式对比 ​

场景传统方式Arthas 方式
看代码是否生效登录服务器找到 class 文件，javap 反编译jad 命令一行搞定
修改线上代码修改源码、编译、打包、发布、重启jad + mc + redefine 热替换
看方法入参、返回值加日志、重启、复现watch 命令动态观测
接口慢逐段打日志、猜测瓶颈trace 命令自动输出链路耗时
CPU 高jstack 抓线程栈，手工分析thread -n 直接找到最忙线程
OOM启动时加 OOM 参数，重启后等复现heapdump 动态 dump，vmtool 查对象
改日志级别修改 logback.xml、重启ognl 一行命令实时修改
获取 Spring Bean写临时 Controller 暴露接口ognl 直接获取任意 Bean

适用场景 ​

  • 线上问题定位：CPU 飙升、内存泄漏、线程死锁、接口响应慢
  • 无代码侵入排查：不改一行代码，不重启应用
  • 代码与配置确认：验证发布版本是否正确、配置是否生效
  • 热修复：紧急 bug 无需发版，直接热替换 class
  • 性能诊断：方法级耗时统计、调用链路追踪

mc + redefine（热替换 Class） ​

在不重启进程的情况下，用编译后的新 class 替换已加载的 class。

bash
# 第一步：修改源码后，编译
mc /tmp/UserService.java -d /tmp/output

# 指定 classLoader 编译
mc -c <classLoaderHash> /tmp/UserService.java -d /tmp/output

# 第二步：热替换
redefine /tmp/output/com/example/service/UserService.class

# 一次替换多个 class
redefine -c <classLoaderHash> /tmp/output/com/example/service/UserService.class /tmp/output/com/example/service/OrderService.class

热修复约束：

生产环境使用注意事项 ​

1. 权限控制 ​

  • 生产环境使用 Arthas 需要审批流程。
  • 建议通过 Tunnel Server 统一管理，记录操作审计日志。
  • 限制能够 attach 的用户和进程。

2. 性能影响 ​

  • watch、trace、tt 都有性能开销，高并发接口慎重使用。
  • 优先使用条件表达式缩小范围（如 #cost>100、params[0]==100）。
  • 观测完毕后及时 Ctrl+C 退出或使用 -n 限制次数。
  • profiler 采样建议控制在 30-60 秒，避免长时间采集。
  • vmtool 的 getInstances 可能触发 GC，谨慎使用。

3. 安全问题 ​

  • OGNL 可以执行任意代码，默认可达性极强。
  • redefine 可能破坏类的结构，导致 JVM 不稳定。
  • 生产环境建议禁用或审计 ognl 和 redefine 命令。

4. 操作规范 ​

  • 操作前记录当前状态（如 quick start 前的 dashboard 截图）。
  • 操作完一个命令后及时确认结果，再执行下一步。
  • 热替换后务必用 jad 验证，并记录替换内容。
  • 修改日志级别后记得改回原级别。
