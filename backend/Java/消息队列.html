1. MQ 基础 ​

1.1 什么是消息队列 ​

消息队列（Message Queue，简称 MQ）是一种跨进程的通信机制，用于在分布式系统中传递数据。生产者将消息发送到队列，消费者从队列中获取并处理消息。

核心作用：

作用说明
解耦生产者和消费者各自独立演进，不直接依赖对方的接口
异步非阻塞通信，生产者发送后立即返回，消费者异步处理
削峰填谷瞬时流量先进入队列，消费者按自身能力慢慢消费，避免系统被突发流量冲垮

1.2 核心概念 ​

概念说明
Producer（生产者）发送消息的一方
Consumer（消费者）接收并处理消息的一方
Broker（代理/中间件服务器）消息队列的服务端，负责存储和转发消息
Topic（主题）消息的逻辑分类，Kafka 中核心概念
Queue（队列）消息的存储载体，RabbitMQ 中核心概念
Message（消息）传输的数据单元，通常包含业务数据和元信息

1.3 消息模型 ​

点对点模型（Point-to-Point） ​

Producer --> Queue --> Consumer
Producer --> Queue --> Consumer
1
  • 一条消息只会被一个消费者消费
  • 消息消费后从队列中移除
  • 典型代表：RabbitMQ 的直连模式

发布订阅模型（Publish / Subscribe） ​

Producer --> Topic --> Subscriber A
                   --> Subscriber B
                   --> Subscriber C
Producer --> Topic --> Subscriber A
                   --> Subscriber B
                   --> Subscriber C
1
2
3
  • 一条消息可以被多个消费者订阅
  • 发布者不直接与订阅者通信
  • 典型代表：Kafka 的 Topic & Consumer Group

2. RabbitMQ（重点） ​

RabbitMQ 是基于 AMQP 0-9-1 协议的开源消息中间件，使用 Erlang 语言开发。在 Java 生态中通过 Spring AMQP / RabbitMQ Java Client 集成。

2.1 基础概念 ​

核心组件 ​

组件说明
Exchange（交换机）生产者发送消息的目标，根据路由规则将消息分发到队列
Queue（队列）存储消息的缓冲区，消费者从队列拉取消息
Binding（绑定）将 Exchange 与 Queue 关联，并指定 Routing Key
Routing Key（路由键）消息携带的标签，Exchange 根据它和 Binding Key 匹配决定投递到哪个队列
Virtual Host（虚拟主机）逻辑隔离单元，一个 Broker 下可建多个 VHost，每个 VHost 有自己的 Exchange/Queue/Binding

消息流转流程 ​

Producer --> Exchange --> (Binding) --> Queue --> Consumer
Producer --> Exchange --> (Binding) --> Queue --> Consumer
1
  1. 生产者发送消息到 Exchange
  2. Exchange 根据 类型 和 Routing Key 匹配 Binding
  3. 消息被路由到一个或多个 Queue
  4. 消费者从 Queue 中拉取或等待推送消息

2.2 Exchange 类型 ​

RabbitMQ 提供四种 Exchange 类型，理解它们是使用 RabbitMQ 的基础。

Direct Exchange（直连交换机） ​

路由规则：Routing Key 完全匹配 Binding Key。

java
// 声明 Direct Exchange
channel.exchangeDeclare("direct.exchange", BuiltinExchangeType.DIRECT);

// 声明队列
channel.queueDeclare("order.queue", true, false, false, null);
channel.queueDeclare("payment.queue", true, false, false, null);

// 绑定队列到 Exchange，指定 Binding Key
channel.queueBind("order.queue", "direct.exchange", "order");
channel.queueBind("payment.queue", "direct.exchange", "payment");

// 发送消息：Routing Key = "order" --> order.queue
channel.basicPublish("direct.exchange", "order", null, "订单消息".getBytes());

Java 配置 ​

java
@Configuration
@EnableRabbit
public class RabbitConfig {

    @Bean
    public RabbitTemplate rabbitTemplate(ConnectionFactory connectionFactory) {
        RabbitTemplate rabbitTemplate = new RabbitTemplate(connectionFactory);
        // 设置 JSON 序列化
        rabbitTemplate.setMessageConverter(new Jackson2JsonMessageConverter());
        // 开启 mandatory（消息无法路由时触发 ReturnCallback）
        rabbitTemplate.setMandatory(true);
        // 确认回调
        rabbitTemplate.setConfirmCallback((correlationData, ack, cause) -> {
            if (ack) {
                System.out.println("消息发送成功: " + correlationData);
            } else {
                System.err.println("消息发送失败: " + cause);
            }
        });
        // 回退回调
        rabbitTemplate.setReturnsCallback(returned -> {
            System.err.println("消息被退回: " + returned.getMessage()
                    + ", replyCode: " + returned.getReplyCode()
                    + ", replyText: " + returned.getReplyText()
                    + ", exchange: " + returned.getExchange()
                    + ", routingKey: " + returned.getRoutingKey());
        });
        return rabbitTemplate;
    }

    @Bean
    public Jackson2JsonMessageConverter messageConverter() {
        ObjectMapper mapper = new ObjectMapper();
        mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);
        return new Jackson2JsonMessageConverter(mapper);
    }

    @Bean
    public Queue orderQueue() {
        return QueueBuilder.durable("order.queue")
                .deadLetterExchange("dlx.exchange")
                .deadLetterRoutingKey("order.dead")
                .ttl(30000) // 30 秒未消费进入死信
                .maxLength(10000)
                .build();
    }

    @Bean
    public DirectExchange orderExchange() {
        return new DirectExchange("order.exchange");
    }

    @Bean
    public Binding orderBinding() {
        return BindingBuilder.bind(orderQueue())
                .to(orderExchange())
                .with("order.create");
    }
}

@Service
public class OrderProducer {

    @Autowired
    private RabbitTemplate rabbitTemplate;

    /**
     * 发送订单创建消息
     */
    public void sendOrderCreated(OrderDTO order) {
        CorrelationData correlationData = new CorrelationData(UUID.randomUUID().toString());
        // 设置回调数据
        correlationData.getFuture().whenComplete((confirm, ex) -> {
            if (ex != null) {
                System.err.println("确认异常: " + ex.getMessage());
            } else if (confirm.isAck()) {
                System.out.println("Broker 已确认: " + correlationData.getId());
            } else {
                System.err.println("Broker 未确认: " + confirm.getReason());
            }
        });
        rabbitTemplate.convertAndSend("order.exchange", "order.create", order, correlationData);
    }
}

@Component
public class OrderConsumer {

    private static final Logger log = LoggerFactory.getLogger(OrderConsumer.class);

    @RabbitListener(queues = "order.queue", concurrency = "3-5")
    public void handleOrder(
            @Payload OrderDTO order,
            @Headers Map<String, Object> headers,
            Channel channel,
            @Header(AmqpHeaders.DELIVERY_TAG) long deliveryTag) throws IOException {

        try {
            log.info("收到订单消息: {}", order);
            // 业务处理
            processOrder(order);
            // 手动确认
            channel.basicAck(deliveryTag, false);
        } catch (BusinessException e) {
            log.warn("业务异常，拒绝消息: {}", e.getMessage());
            // 拒绝并重新入队
            channel.basicNack(deliveryTag, false, true);
        } catch (Exception e) {
            log.error("处理失败，拒绝消息不入队: {}", e.getMessage());
            // 拒绝且不入队（进入死信队列）
            channel.basicNack(deliveryTag, false, false);
        }
    }

    @RabbitListener(queues = "order.dlq.queue")
    public void handleDeadLetter(OrderDTO order) {
        log.warn("处理死信消息: {}", order);
        // 死信处理：记录日志、告警、补偿等
    }
}

2.4 进阶特性 ​

2.4.1 死信队列（DLX + TTL） ​

死信（Dead Letter）：消息在队列中出现以下情况时会变成死信：

  • 消费者使用 basicNack / basicReject 且 requeue = false
  • 消息 TTL 到期
  • 队列达到最大长度

死信交换机（DLX）：当消息变成死信后，会被重新发布到指定的 DLX，再路由到死信队列。

java
// 普通队列，绑定死信交换机
@Bean
public Queue businessQueue() {
    return QueueBuilder.durable("business.queue")
            .deadLetterExchange("dlx.exchange")       // 死信交换机
            .deadLetterRoutingKey("business.dead")    // 死信路由键
            .ttl(60000)                                // 消息 TTL：60 秒
            .maxLength(5000)                           // 队列最大长度
            .build();
}

// 死信交换机
@Bean
public DirectExchange dlxExchange() {

3. Kafka（重点） ​

Apache Kafka 是分布式流处理平台，核心设计为高吞吐、持久化、可分区、可复制的发布订阅系统。在 Java 生态中通过 Spring Kafka 集成。

3.1 基础概念 ​

核心组件 ​

组件说明
Topic（主题）消息的逻辑分类，对应 RabbitMQ 的 Exchange + Routing Key 组合
Partition（分区）Topic 的物理分片，每个分区是一个有序的不可变日志文件
Offset（偏移量）分区内消息的唯一递增序号，由 Kafka 自动分配
Consumer Group（消费者组）一组消费者的逻辑分组，一条消息只能被组内一个消费者消费
Broker（代理节点）Kafka 服务进程
Controller（控制器）集群中负责管理分区 Leader 选举的节点
ISR（In-Sync Replica）与 Leader 保持同步的副本集合
Leader / Follower分区的读写都由 Leader 处理，Follower 被动复制

消息在 Kafka 中的流转 ​

Producer --> Topic (Partition 0) --> Offset 0, 1, 2, 3...
         --> Topic (Partition 1) --> Offset 0, 1, 2, 3...
         --> Topic (Partition 2) --> Offset 0, 1, 2, 3...

Consumer Group A --> Consumer A-0 (消费 Partition 0)
                --> Consumer A-1 (消费 Partition 1, 2)
Consumer Group B --> Consumer B-0 (消费 Partition 0, 1, 2)
Producer --> Topic (Partition 0) --> Offset 0, 1, 2, 3...
         --> Topic (Partition 1) --> Offset 0, 1, 2, 3...

@Service
public class OrderEventProducer {

    @Autowired
    private KafkaTemplate<String, Object> kafkaTemplate;

    private static final Logger log = LoggerFactory.getLogger(OrderEventProducer.class);

    /**
     * 发送订单创建事件
     */
    public void sendOrderCreated(OrderEvent event) {
        // 使用订单 ID 作为 key，确保同一订单进入同一分区
        ListenableFuture<SendResult<String, Object>> future =
                kafkaTemplate.send("order-events", event.getOrderId(), event);

        future.whenComplete((result, ex) -> {
            if (ex == null) {
                RecordMetadata metadata = result.getRecordMetadata();
                log.info("消息发送成功: topic={}, partition={}, offset={}, key={}",
                        metadata.topic(), metadata.partition(),
                        metadata.offset(), event.getOrderId());
            } else {
                log.error("消息发送失败: key={}, error={}", event.getOrderId(), ex.getMessage());
                // 可以写入本地重试表或发送到死信
                handleSendFailure(event, ex);
            }
        });
    }

    /**
     * 发送带回调的异步消息
     */
    public void sendWithCallback(OrderEvent event) {
        kafkaTemplate.send("order-events", event.getOrderId(), event)
                .addCallback(new ListenableFutureCallback<>() {
                    @Override
                    public void onFailure(Throwable ex) {
                        log.error("发送失败: {}", ex.getMessage());
                    }

                    @Override
                    public void onSuccess(SendResult<String, Object> result) {
                        log.info("发送成功: offset={}", result.getRecordMetadata().offset());
                    }
                });
    }

    /**
     * 同步发送（不推荐用于核心业务，会阻塞）
     */
    public void sendSync(OrderEvent event) throws ExecutionException, InterruptedException {
        SendResult<String, Object> result =
                kafkaTemplate.send("order-events", event.getOrderId(), event).get();
        log.info("同步发送成功: offset={}", result.getRecordMetadata().offset());
    }
}

@Component
public class ManualRetryConsumer {

    @Autowired
    private KafkaTemplate<String, Object> kafkaTemplate;

    private static final String DLT_TOPIC = "order-events-dlt";

    @KafkaListener(topics = "order-events", groupId = "retry-group")
    public void consume(ConsumerRecord<String, OrderEvent> record,
                        Acknowledgment ack) {
        try {
            process(record.value());
            ack.acknowledge();
        } catch (RetryableException e) {
            int retryCount = getRetryCount(record.headers());
            if (retryCount < 3) {
                // 发送到重试主题（延迟主题）
                kafkaTemplate.send("order-events-retry", record.key(), record.value());
            } else {
                // 超过重试次数，发送到 DLT
                kafkaTemplate.send(DLT_TOPIC, record.key(), record.value());
            }
            ack.acknowledge();
        }
    }

    private int getRetryCount(Headers headers) {
        Header header = headers.lastHeader("retry-count");
        if (header == null) return 0;
        return Integer.parseInt(new String(header.value()));
    }

    private void process(OrderEvent event) {
        // 业务处理
    }

4.2 选型建议 ​

选 RabbitMQ 的场景 ​

  • 需要灵活的路由策略：复杂的消息路由规则（如按内容、通配符匹配）
  • 低延迟敏感应用：金融交易、实时通知，要求毫秒级甚至微秒级延迟
  • 传统企业集成：大量使用 AMQP 协议的系统
  • 消息数量可控：吞吐量需求在万级/秒以内
  • 需要延迟消息/死信队列：RabbitMQ 原生支持 DLX + TTL，实现简单
  • 需求快速迭代验证：RabbitMQ 概念简单，上手快

选 Kafka 的场景 ​

  • 超高吞吐量：需要百万级/秒的消息处理能力
  • 日志收集与监控：海量日志/指标的采集和聚合
  • 事件溯源 / CQRS：需要消息持久化和回溯重放
  • 流处理：Kafka Streams / ksqlDB 实现复杂流计算
  • 数据管道 / ETL：大数据生态集成（Flink、Spark、Hadoop）
  • 削峰填谷并重放：消费能力不足时可以先积压，恢复后重放
  • 多消费者独立消费：不同业务线独立消费同一份数据

混合架构 ​

在实际的大型项目中，RabbitMQ 和 Kafka 可以并存：

场景推荐消息队列原因
用户注册 → 发送欢迎邮件RabbitMQ路由简单，延迟低
支付成功 → 更新订单状态RabbitMQ需要死信队列进行补偿
订单创建 → 触发风控分析Kafka上下游多个系统订阅
应用日志收集Kafka吞吐量大，按时间保留
实时数仓 ODS 层Kafka对接 Flink/Spark
秒杀流量削峰Kafka超高瞬时流量
管理后台实时通知RabbitMQ低延迟，广播推送

@Component

    @Autowired
    private LocalMessageMapper messageMapper;

    @Autowired
    private RabbitTemplate rabbitTemplate;

    @Scheduled(fixedDelay = 5000) // 每 5 秒扫描一次
    public void relayMessages() {
        List<LocalMessage> pending = messageMapper.selectList(
                new LambdaQueryWrapper<LocalMessage>()
                        .eq(LocalMessage::getStatus, 0)
                        .lt(LocalMessage::getRetryCount, 5)
                        .last("limit 100"));

        for (LocalMessage msg : pending) {
            try {
                rabbitTemplate.convertAndSend(
                        msg.getExchange(),
                        msg.getRoutingKey(),
                        msg.getMessageBody(),
                        new CorrelationData(msg.getBusinessKey()));

                msg.setStatus(1);
                messageMapper.updateById(msg);
            } catch (Exception e) {
                msg.setRetryCount(msg.getRetryCount() + 1);
                msg.setUpdateTime(LocalDateTime.now());
                messageMapper.updateById(msg);
            }
        }
    }
