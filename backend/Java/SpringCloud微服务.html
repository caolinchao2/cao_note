一、微服务概述 ​

1.1 单体架构 vs 微服务架构 ​

维度单体架构微服务架构
定义所有功能模块打包在一个进程中部署每个功能模块独立部署为小型服务
开发效率项目初期开发快，后期耦合严重每个服务独立开发，技术栈灵活
部署发布即停服，影响全部功能独立部署，灰度发布
伸缩性只能整体水平扩展，资源浪费按需伸缩，精细化资源分配
容错性一个模块 OOM 拖垮整个进程故障隔离，熔断降级保护
团队协作代码冲突频繁，沟通成本高每个团队负责一个或几个服务
运维成本低，仅需维护一个应用高，需要服务发现/配置中心/网关/监控等基础设施

二、Nacos 服务发现与配置中心 ​

Nacos（Dynamic Naming and Configuration Service）是阿里巴巴开源的服务发现与配置管理平台，在 Spring Cloud Alibaba 体系中充当着注册中心和配置中心的双重角色。

2.1 Nacos 核心概念 ​

概念说明
Service服务实例的逻辑分组
Instance提供服务的具体进程实例（IP:Port）
Cluster同一服务下的实例集群（如北京/上海机房）
Data ID配置文件的唯一标识，通常为 ${spring.application.name}-${profile}.${file-extension}
Group配置分组，默认 DEFAULT_GROUP
Namespace命名空间，用于多环境隔离（dev / test / prod）
Protect Threshold保护阈值（0-1），当健康实例比例低于该值时触发保护模式，将不健康实例也返回给调用方

使用 DiscoveryClient 获取服务实例 ​

java
import org.springframework.cloud.client.discovery.DiscoveryClient;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/discovery")
public class DiscoveryController {

    private final DiscoveryClient discoveryClient;

    public DiscoveryController(DiscoveryClient discoveryClient) {
        this.discoveryClient = discoveryClient;
    }

    @GetMapping("/instances/{serviceId}")
    public List<?> getInstances(@PathVariable String serviceId) {
        // 获取某个服务的所有实例
        return discoveryClient.getInstances(serviceId);
    }

    @GetMapping("/services")
    public List<String> getServices() {
        // 获取所有已注册的服务名
        return discoveryClient.getServices();
    }
}

健康检查机制 ​

Nacos 客户端默认每 5 秒 向服务端发送一次心跳。服务端在 15 秒 内未收到心跳则将该实例标记为不健康，30 秒 未收到则删除实例。

yaml
spring:
  cloud:
    nacos:
      discovery:
        heart-beat-interval: 5000          # 心跳间隔（毫秒）
        heart-beat-timeout: 15000          # 心跳超时（毫秒）
        ip-delete-timeout: 30000           # 实例删除超时（毫秒）

    nacos:

三、Spring Cloud Gateway 网关 ​

Spring Cloud Gateway 是基于 Spring WebFlux 的 API 网关，底层使用 Reactor 框架和 Netty 运行时，非阻塞 IO 支撑高并发。注意：Gateway 依赖 Netty，因此不能在传统的 Servlet 容器（Tomcat）中运行，也不兼容 spring-boot-starter-web。

3.1 核心概念 ​

概念说明
Route（路由）网关的基本构建块，由 ID、目标 URI、断言集合、过滤器集合组成
Predicate（断言）Java 8 Predicate 的实现，匹配 HTTP 请求条件，决定是否路由
Filter（过滤器）对请求和响应进行修改的拦截器，分为 GatewayFilter（局部）和 GlobalFilter（全局）

/**
 * 全局请求日志过滤器
 * 为每个请求添加 Trace ID，便于链路追踪
 */
@Component
public class TraceIdGlobalFilter implements GlobalFilter, Ordered {

    private static final Logger log = LoggerFactory.getLogger(TraceIdGlobalFilter.class);

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String traceId = UUID.randomUUID().toString().replace("-", "").substring(0, 16);

        ServerHttpRequest request = exchange.getRequest().mutate()
                .header("X-Trace-Id", traceId)
                .build();

        ServerWebExchange mutatedExchange = exchange.mutate().request(request).build();

        // 记录请求日志
        log.info("[{}] {} {}",
                traceId,
                request.getMethod(),
                request.getURI().getPath());

        return chain.filter(mutatedExchange);
    }

    /**
     * 返回 order 值，数值越小优先级越高
     */
    @Override
    public int getOrder() {
        return Ordered.LOWEST_PRECEDENCE;
    }

java
import org.springframework.cloud.gateway.filter.GatewayFilter;
import org.springframework.cloud.gateway.filter.factory.AbstractGatewayFilterFactory;
import org.springframework.http.HttpHeaders;
import org.springframework.http.server.reactive.ServerHttpRequest;
import org.springframework.stereotype.Component;

/**
 * 自定义过滤器工厂：移除指定请求头
 * 使用方式：- RemoveRequestHeaderSuffix=suffix1,suffix2
 */
@Component
public class RemoveRequestHeaderSuffixGatewayFilterFactory
        extends AbstractGatewayFilterFactory<RemoveRequestHeaderSuffixGatewayFilterFactory.Config> {

    public RemoveRequestHeaderSuffixGatewayFilterFactory() {
        super(Config.class);
    }

    @Override
    public GatewayFilter apply(Config config) {
        return (exchange, chain) -> {
            ServerHttpRequest request = exchange.getRequest();
            HttpHeaders headers = request.getHeaders();

            headers.keySet().stream()
                    .filter(key -> config.getSuffixes().stream().anyMatch(key::endsWith))
                    .forEach(key -> {
                        request.mutate().headers(h -> h.remove(key));
                    });

            return chain.filter(exchange.mutate()
                    .request(request.mutate().build())
                    .build());
        };
    }

    public static class Config {
        private String suffixes;

        public String getSuffixes() {
            return suffixes;
        }

        public void setSuffixes(String suffixes) {
            this.suffixes = suffixes;
        }
    }
}

                        request.mutate().headers(h -> h.remove(key));
                    });

            return chain.filter(exchange.mutate()
                    .request(request.mutate().build())
                    .build());
        };
    }

    public static class Config {
        private String suffixes;

        public String getSuffixes() {
            return suffixes;
        }

        public void setSuffixes(String suffixes) {
            this.suffixes = suffixes;
        }
    }

import com.alibaba.csp.sentinel.annotation.SentinelResource;
import com.alibaba.csp.sentinel.slots.block.BlockException;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/user")
public class UserController {

    /**
     * 使用 @SentinelResource 定义资源
     * value: 资源名称（唯一）
     * blockHandler: 流控/熔断触发时的回调（处理 BlockException）
     * fallback: 所有异常的回调（包括业务异常）
     */
    @GetMapping("/{id}")
    @SentinelResource(
            value = "getUserById",
            blockHandler = "getUserByIdBlockHandler",
            fallback = "getUserByIdFallback"

        if (id == null || id <= 0) {
            throw new IllegalArgumentException("invalid id");

        // 模拟业务调用
        return new User(id, "name_" + id);

                      ↑                                       │

熔断策略说明判定条件
慢调用比例响应时间超过 RT 的请求比例达到阈值maxRt > 阈值ms 且比例 > ratio
异常比例异常数占总请求数的比例达到阈值errorCount / totalCount > ratio

import com.alibaba.csp.sentinel.slots.block.degrade.DegradeRule;
import com.alibaba.csp.sentinel.slots.block.degrade.DegradeRuleManager;
import jakarta.annotation.PostConstruct;
import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.List;

@Component
public class SentinelDegradeRuleConfig {

    @PostConstruct
    public void initDegradeRules() {
        List<DegradeRule> rules = new ArrayList<>();

        // 规则1：慢调用比例熔断
        DegradeRule slowRule = new DegradeRule("getUserById");
        slowRule.setGrade(RuleConstant.DEGRADE_GRADE_RT);       // 慢调用
        slowRule.setCount(500);                                  // RT 超过 500ms
        slowRule.setTimeWindow(10);                              // 熔断时长 10 秒
        slowRule.setMinRequestAmount(5);                         // 触发熔断的最小请求数
        slowRule.setSlowRatioThreshold(0.5);                     // 慢调用比例阈值 50%
        slowRule.setStatIntervalMs(1000);                        // 统计时间窗口 1s
        rules.add(slowRule);

        // 规则2：异常比例熔断
        DegradeRule exceptionRatioRule = new DegradeRule("createOrder");
        exceptionRatioRule.setGrade(RuleConstant.DEGRADE_GRADE_EXCEPTION_RATIO);
        exceptionRatioRule.setCount(0.2);                        // 异常比例 20%
        exceptionRatioRule.setTimeWindow(30);                    // 熔断 30 秒
        exceptionRatioRule.setMinRequestAmount(10);
        rules.add(exceptionRatioRule);

        // 规则3：异常数熔断
        DegradeRule exceptionCountRule = new DegradeRule("payOrder");
        exceptionCountRule.setGrade(RuleConstant.DEGRADE_GRADE_EXCEPTION_COUNT);
        exceptionCountRule.setCount(10);                         // 10 个异常
        exceptionCountRule.setTimeWindow(60);
        exceptionCountRule.setMinRequestAmount(5);
        rules.add(exceptionCountRule);

        DegradeRuleManager.loadRules(rules);
    }

6.4 AT 模式（自动补偿） ​

AT 模式是 Seata 最核心的模式，对业务代码的侵入性极低。其核心机制是自动生成逆向 SQL 实现回滚。

一阶段：TM 开始全局事务 -> RM 执行业务 SQL -> 生成 undo_log -> 提交本地事务 -> 上报分支状态
                    ↓
二阶段提交：TC 通知所有 RM 删除 undo_log（全局提交）
                    ↓
二阶段回滚：TC 通知 RM -> RM 根据 undo_log 生成逆向 SQL 恢复数据
一阶段：TM 开始全局事务 -> RM 执行业务 SQL -> 生成 undo_log -> 提交本地事务 -> 上报分支状态
                    ↓
二阶段提交：TC 通知所有 RM 删除 undo_log（全局提交）
                    ↓
二阶段回滚：TC 通知 RM -> RM 根据 undo_log 生成逆向 SQL 恢复数据

6.5 TCC 模式（Try-Confirm-Cancel） ​

TCC 模式需要业务方自己实现 Try、Confirm、Cancel 三个方法，相比 AT 模式更灵活，性能更好。

Try:     资源预留（如冻结库存、预扣金额）
Confirm: 确认执行业务操作（使用 Try 阶段预留的资源）
Cancel:  取消业务操作（释放 Try 阶段预留的资源）

import io.seata.rm.tcc.api.BusinessActionContext;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class AccountTccServiceImpl implements AccountTccService {

    private final AccountMapper accountMapper;
    private final AccountFreezeMapper freezeMapper;

    public AccountTccServiceImpl(AccountMapper accountMapper,
                                  AccountFreezeMapper freezeMapper) {
        this.accountMapper = accountMapper;
        this.freezeMapper = freezeMapper;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public boolean prepare(BusinessActionContext context, Long userId, BigDecimal amount) {
        // 检查余额
        Account account = accountMapper.selectById(userId);
        if (account.getBalance().compareTo(amount) < 0) {
            throw new RuntimeException("余额不足");
        }
        // 扣减余额（可冻结金额）
        accountMapper.updateFrozenBalance(userId, amount);
        // 记录冻结记录
        freezeMapper.insert(new AccountFreeze(userId, amount, AccountFreeze.STATUS_TRY));
        return true;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public boolean confirm(BusinessActionContext context) {
        // 正式扣减：将冻结金额从冻结字段清除
        Long userId = Long.valueOf(context.getActionContext("userId").toString());
        freezeMapper.updateStatus(userId, AccountFreeze.STATUS_TRY, AccountFreeze.STATUS_CONFIRM);
        return true;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public boolean cancel(BusinessActionContext context) {
        // 撤销：归还冻结金额
        Long userId = Long.valueOf(context.getActionContext("userId").toString());
        BigDecimal amount = new BigDecimal(context.getActionContext("amount").toString());
        accountMapper.unfreezeBalance(userId, amount);
        freezeMapper.updateStatus(userId, AccountFreeze.STATUS_TRY, AccountFreeze.STATUS_CANCEL);
        return true;
    }

选型建议：

  • AT 模式：首选，适合绝大多数业务场景，改造最小。
  • TCC 模式：对性能要求极高，或需要精细化控制资源锁定范围。

优点：

  1. 接口契约统一：DTO 和 Feign 接口由服务提供者维护，消费者以 JAR 方式引入，保证参数和返回值一致。

import com.example.common.exception.BizException;
import com.example.common.dto.Result;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    @ExceptionHandler(BizException.class)
    @ResponseStatus(HttpStatus.OK)
    public Result<Void> handleBizException(BizException e) {
        log.warn("业务异常: {}", e.getMessage());
        return Result.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(IllegalArgumentException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleIllegalArgument(IllegalArgumentException e) {
        return Result.error(400, e.getMessage());
    }

    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "系统繁忙，请稍后再试");
    }
}
